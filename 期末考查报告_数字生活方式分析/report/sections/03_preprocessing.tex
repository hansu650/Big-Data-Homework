\section{数据预处理}

本章的目的在于说明数据进入模型前如何检查质量、构造特征并控制目标泄漏。预处理不是简单的格式整理，而是保证后续结果可信的基础：若缺失、重复、异常范围或目标泄漏未处理，分类、回归和聚类结果都会被扭曲。

\subsection{数据质量检查}

预处理质量检查结果保存于 \texttt{results/preprocessing\_quality\_check.csv}。表 \ref{tab:preprocessing-quality-check} 给出精简汇总。检查结果显示，原始数据包含 3500 条记录和 24 个字段，缺失值总数为 0，重复行数量为 0，重复 \texttt{id} 数量为 0。对年龄、设备使用时长、手机解锁、通知数、社交媒体时长、学习时长、运动天数、睡眠时长、睡眠质量、生产力得分和数字依赖得分等数值字段进行合理范围检查后，未发现需要删除的记录。

\subsection{特征工程}

原始字段能够描述数字生活方式的基础状态，但部分关系需要通过派生特征表达。例如，单纯的通知总数不能反映单位设备使用时间内的通知密度，社交媒体分钟数和学习分钟数也可以转换为小时或比例。本文据此生成了 \texttt{social\_media\_hours}、\texttt{study\_hours}、\texttt{notifications\_per\_device\_hour}、\texttt{unlocks\_per\_device\_hour}、\texttt{device\_to\_sleep\_ratio}、\texttt{activity\_sleep\_interaction} 和 \texttt{social\_to\_study\_ratio}。质量检查表显示这些工程特征均已成功生成。

\begin{lstlisting}[language=Python,caption={行为与生活习惯工程特征示例}]
def add_behavior_features(df):
    out = df.copy()
    eps = 1e-6
    out["social_media_hours"] = out["social_media_mins"] / 60.0
    out["study_hours"] = out["study_mins"] / 60.0
    out["notifications_per_device_hour"] = (
        out["notifications_per_day"] / out["device_hours_per_day"].clip(lower=eps)
    )
    out["unlocks_per_device_hour"] = (
        out["phone_unlocks"] / out["device_hours_per_day"].clip(lower=eps)
    )
    out["device_to_sleep_ratio"] = (
        out["device_hours_per_day"] / out["sleep_hours"].clip(lower=eps)
    )
    return out
\end{lstlisting}

\subsection{目标泄漏控制}

目标泄漏控制是本文建模流程的重点。分类任务预测 \texttt{high\_risk\_flag} 时，主模型不使用 \texttt{anxiety\_score}、\texttt{depression\_score}、\texttt{stress\_level}、\texttt{happiness\_score}、\texttt{focus\_score}、\texttt{productivity\_score} 和 \texttt{digital\_dependence\_score}，因为这些变量属于心理、效率或结果性质字段，若直接输入模型，会高估高风险筛查能力。

回归任务同样排除 \texttt{high\_risk\_flag} 和其他 outcome 字段；当预测 \texttt{digital\_dependence\_score} 时，不使用 \texttt{productivity\_score} 等结果变量；当预测 \texttt{productivity\_score} 时，也不使用 \texttt{digital\_dependence\_score}。聚类任务则只使用数字行为与生活习惯数值特征，不将人口背景类别变量、设备类别变量和任何结果变量放入聚类训练。

\begin{lstlisting}[language=Python,caption={任务级特征排除逻辑示例}]
if task == "classification":
    excluded.add(CLASSIFICATION_TARGET)
    excluded.update(HIGH_RISK_LEAKAGE_COLUMNS)
elif task == "regression":
    excluded.add(target)
    excluded.update(OUTCOME_COLUMNS)
elif task == "clustering":
    X = data[get_clustering_feature_columns(data)].copy()
\end{lstlisting}

上述规则使三类任务的输入空间保持一致、可解释且尽量避免结果变量反向进入模型。
